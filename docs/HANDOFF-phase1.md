## 3. Phase 1 결정 로그 (ADR-0002의 원료)

### D1. MVP 정책 범위 (이슈 A1)
- **결정**: ⓐ자가판정 가능 ⓑ페르소나 적합 ⓒ요건 원자 공유 기준 유지. 확정 3종(청년월세 특별지원(면제군 한정)·청년 주택드림 청약통장·청년전용 버팀목 전세자금대출) + 주거급여 청년 분리지급은 신규 원자 비용(ⓒ) 검토 후 4종째 결정. 범위 확장은 출시 후 '미커버 수요 지표'(5장 신설)로 결정.
- **기각된 대안**: (i) 면제군 해제 — 원안의 가구합산 제외 원칙과 충돌, 원칙 재작성 부담으로 기각. 확장 시점 재검토로 보류 (PRD 6장·8장에 명시됨). (ii) 후보 8종 확장 — 정규화·골든셋·갱신 감시 비용이 정책 수에 비례(약 2.5배), "정확도 우선"과 상충. (iii) 코퍼스(자격질문 143건) 대조 선행 — 속도 우선으로 생략, 미커버 수요 지표가 대체. 코퍼스 대조는 확장 시점 보조 근거로 강등. (iv) ⓓ(판정 완결성) 기준 추가 — 논의됐으나 최종 미채택, 확장 시점 재검토 자산으로 매트릭스에 보존.
- **근거 데이터**: docs/persona-policy-matrix.md. 핵심 발견: ① 페르소나 소득(월 200~250만) 구간 안을 판정 경계 2개가 통과(청년월세 중위60%≈월215만 지점, 주거급여 중위48%≈월232만 지점) — 골든셋은 이 경계 대역 과표집 필요. ② 면제군 조건 ④의 "시군구청장 인정" = 행정재량 값 유형(자가입력 불가+선발절차 아님) 발견 — DOMAIN.md 원자 값 유형 분류에 추가 후보. ③ 중기청 대출은 청년버팀목으로 통합 소멸, 청년도약계좌는 2025.12 신규 종료(후속: 청년미래적금) — 정책 존속 자체가 고갱신 대상임을 실증 (PRD 9장에 반영됨). ※매트릭스 수치는 2026-07 웹 검색 기반 근사치, 구현 시 공식 출처 재검증 필수.

### D2. 제외 원칙 정밀화 — "자격 요건 vs 선발 절차" (사용자 발견)
- **결정**: 추첨·선발·예산 소진·모집기간은 자격 요건이 아닌 선발 절차·신청 시기 제약 → 제외 사유에서 삭제. 해당 정책은 판정 대상이며 결과에 선발 방식·신청 시기를 고지. 서비스 의미론("신청 자격 판정, 선발·수혜 미보장")과 정합화.
- **파급 반영 완료**: PRD 6장 일반 원칙, Story 3-2 (선발절차 고지 Detail 신설), 4-state '자가판정 불가' 정의(추첨 삭제), 8장 Tier 2 정의, 청년수당 제외 근거(가구소득 단독으로 축소).

### D3. 오판율 재정의 (이슈 A2·A3)
- **결정**: 골든셋(규정 기준 사람 검수 정답) 대비 로직 정확도로 정의 교체 — 기존 정의("실제 탈락")는 무인증·미저장 특성상 관측 불가. FP(과대판정율)/FN(과소판정율)으로 분해, **비대칭 관리**: FP는 출시 게이트(상한 TODO 유지), FN은 측정·보고만. 잔여 리스크(행정 재량·서류 미비 등)는 지표가 아니라 추정 고지(Story 2-2)+면책 설계(9장)가 담당 — 5장 각주로 명시됨.

### D4. 입력 방식 = 가이드형 분기 질문 (이슈 A4)
- **결정**: MVP는 (b) 일상어 분기 질문만. 판정 필요값(나이·무주택·임차형태·세대독립성·본인소득·본인재산)을 짧은 분기 질문으로, 세대독립성을 질문 흐름 초반에 확정.
- **기각**: (a) 자유 자연어+LLM 파싱 — 파싱 오류가 오판의 새 원천, LLM 런타임 의존(판정 도달 속도·비용), 자유 텍스트 개인정보 유입. 기각 사유는 PRD 6장 ①에 이탤릭으로 박제됨 (에이전트의 재제안 방지 앵커).
- **보류**: (c) 절충(첫 입력만 자유 텍스트, 후보 추리기 한정, 판정값은 구조화 확인) — 확장 후보로 8장 ③에 명시됨.
- **파급 반영 완료**: 해결책 ①, Story 1-1(제목+Detail 2개), H1 문구("일상어 기반 입력"으로 중립화), 입력 완료율 정의, 8장 ③.

### D5. 기타 반영 (B1~B5, C1~C2)
- B1: 0장 '서비스 정의와 약속' 신설 (확정 문구 + 신청/수혜 구분 + "빠짐없이는 비전, MVP 확장 근거 아님" + 무인증)
- B2: '판정 불가·오류율' → '추가 확인 필요율'(locus 사용자)과 '자가판정 불가 노출율'(locus 시스템)로 분리
- B3: Story 3-2 재산 예외 → "'모름' 답변 시 판정 중단 없이 불확실 표기로 진행" 원칙으로 재작성, 요건별 상세는 요건 원자 spec 소유
- B4: '유효성 인식'(MVP 계측 외), '인증·기술 마찰 불만율'(간접 신호 관찰, 발생=설계 위반 신호) 표시
- B5: Story 1-2에 MVP 스케일 명시 (카탈로그 탐색 아닌 MVP 정책 결정론적 필터링)
- C1: 7장 헤더에 이관 계획 명시 (Epic/Story→SPEC, 4-state→DOMAIN, 이관 전까지 7장이 원본)
- C2: "기능정의서" → "SPEC(기능 명세)" 명칭 통일

## 5. 즉시 액션 (Code 세션 순서)

1. 2장의 파일 배치 수행
2. **ADR-0002 작성**: adr/0000-template.md 형식. 제목 "MVP 정책 범위와 입력 방식". Context/Decision/기각된 대안은 본 문서 3장 D1~D4에서, 근거 데이터는 docs/persona-policy-matrix.md 참조로. 상태 proposed로 작성 → 사람 리뷰 후 accepted 전환.
3. 사람 통독 완료 신호 후: `git commit -m "docs: PRD 확정 + ADR-0002 (Phase 1)"`
4. Phase 2: "PRD.md 6장 스코프 결정을 SPEC.md 1장 범위표(기능/정책 × in/out/later + 한 줄 사유)로 변환" — 내용은 전부 확정 상태라 기계적 변환. PRD와 모순 생기면 PRD가 이김.

## 6. 스타일 계약 (이 프로젝트에서 사람이 기대하는 것)

- 직접적 분석 + 명시적 트레이드오프. 결정에는 항상 기각된 대안과 사유를 남길 것.
- 제품 문서는 append-only, ID 영구, ADR은 supersede. ARCHITECTURE.md는 accept된 ADR로만 갱신.
- CLAUDE.md의 DO NOT 준수: contracts/ 무단 수정 금지, 제품 문서 직접 수정 금지(diff 제안), ADR 없이 구조 변경 금지, 범위표 out/later 구현 금지.
- 문서는 한국어, ~다체. 판단이 필요 없는 참조 정보는 개조식, 행동 규칙은 완결 문장.

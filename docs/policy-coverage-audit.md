# 정책 요건 커버리지 감사 — MVP 3종

> 1차 출처 원문의 자격 요건과 `backend/src/main/resources/policies/*.json`의 rule 원자를 대조한 기록.
> 감사일 **2026-08-13**. 이 문서는 발견의 기록이며, 해소는 별도 이슈에서 다룬다(§5).

## 0. 왜 했나

온통청년 청년정책 API 실측 중 청년월세 원문에 `rule`에 없는 요건이 보여 3종 전수로 확대했다. **3종 모두에서 갭이 나왔다.**

개별 값 오류가 아니라 **인코딩 프로세스의 구조적 문제**다 — 원문에서 "판정 가능한 요건"만 골라 담았는데, 고른 기준도 뺀 사유도 기록되지 않았다. 그래서 아래 항목들이 *누락*인지 *의도적 제외*인지 지금은 구분할 수 없다.

## 1. 방법과 증거 등급

| tier | 의미 | 이번 감사에서 |
|---|---|---|
| 1 | 소관 부처·기금의 공식 안내 원문 | 주택도시기금(nhuf.molit.go.kr) 상품안내·대출안내 |
| 2 | 공공기관 재게시·집계 | 온통청년 청년정책 API(한국고용정보원 등록) |
| 3 | 아그리게이터·언론·블로그 | **사용하지 않음** (#33에서 3.37억 오류를 만든 경로) |

**3종 모두 tier 1로 대조했다.** 복지로는 SPA라 자동 수집이 불가해 사람이 본문을 직접 확인했고, 그 과정에서 tier 2·tier 3이 각각 틀린 신호를 준 사례가 드러났다(§4 말미).

**상태 표기**: ✅ 덮음 / 🔴 rule에 없음 / ⚠️ 범위 불일치 / 🟡 자가판정 곤란

**FN — 병역 차감**: 38세이고 병역 4년을 이행한 사람은 원문상 가입 가능한데, `age.max=34`가 잘라내 '부적합'으로 답한다.

**FP — 소득 신고 이력**: 소득이 0원인 무직·학생은 원문상 가입 대상이 아닌데, `income_self ≤ 5천만원`만 보므로 '가능'으로 답한다. 상한만 있고 하한·존재 요건이 없다.

**신청 채널 문제 (F-006)**: `application.url`이 `https://nhuf.molit.go.kr`인데 이 페이지는 **상품 안내 페이지이지 개설 경로가 아니다.** 실제 개설처(취급 은행 창구·앱)를 1차 출처로 확인해 교체해야 한다. — *확인 필요 항목*

**provenance 품질**: 세 원자의 `meta.source`가 모두 `"국토교통부"` 다섯 글자다. URL·조항·확인일이 없어 재검증이 불가능하다.

**소득평가액 산식 정합성**: 원문은 `소득평가액 = 근로+사업+재산+공적이전소득 − 근로·사업소득공제(30%)`다. 우리 역산식은 `세전 근로소득 × 0.7`이라 **순수 근로소득자에게만 성립**한다. MVP 페르소나가 근로소득자라 방어 가능하지만, `income_self`의 `approx` 근거로 명시돼야 한다.

**면제군 ④는 `admin_discretion`(시·군·구청장 재량)** 이다. 게이트에 자가판정 불가 원자가 들어가면 `any_of`가 Kleene 흡수로 UNKNOWN에 갇혀 out_of_scope 경로가 조용히 무력화된다(DOMAIN §3.4). 이슈 #37이 막으려는 실패 모드와 직결된다.

**총재산가액 자가판정 난이도**: `총재산가액 = 일반재산 + 자동차 − 부채`인데, 일반재산에 전월세보증금·회원권·선박·항공기까지 포함되고 부채는 **용도가 맞는 것만**(임차보증금 마련) 차감된다. `asset_self`를 단순 금액 입력으로 물으면 사용자가 이 계산을 정확히 수행하지 못한다. 요건 추가 시 `approx` 처리할지 자가판정 곤란으로 분류할지 결정이 필요하다.

**신청기간·선발 방식**: 신청접수 `2026-03-30 09:00 ~ 2026-05-29 16:00`, 선정자 공지 `2026-09-14`로 **감사일 기준 접수 종료**다. 현재 `application.period`는 `"사업 공고별 신청기간 확인 필요 — 상시 아님"`으로 방향은 맞으나 실제 날짜가 없다.

**`selection_method`는 사실과 반대다.** 현재 값은 `"선발 없음 — 요건 충족 시 지원(추첨·선착순 아님)"`인데, 원문은 **"6만명을 선정할 예정(지원자가 많을 경우 소득, 재산 등이 낮은 인원을 선정)"** 이다. 정원이 있고 초과 시 우선순위 선발이 이뤄진다. CLAUDE.md가 서비스 정의 첫 문단에서 *"'신청 가능'은 신청 자격 충족을 의미하며, 선발·수혜를 보장하지 않는다"* 고 못 박은 바로 그 지점에서, 데이터가 반대로 말하고 있다(F-007).

### tier 2가 틀린 신호를 준 사례

온통청년 API는 이 정책에 대해 `sprtSclLmtYn: "N"`(지원규모 제한 **없음**)을 반환했다. tier 1 원문은 "6만명 선정 예정, 초과 시 선별"이다. **API 값만 믿었으면 '제한 없음'으로 인코딩했을 것이다.**

`sprtSclCnt: "60000"`이 함께 오긴 하나 `sprtSclLmtYn`과 모순되며, 어느 쪽이 유효한지 API만으로는 판별할 수 없다. ADR-0008에서 "공공 API를 값의 출처로 쓰지 않고 변경 신호로만 쓴다"는 결정의 실증 근거다.

### tier 3이 틀린 신호를 준 사례

웹 검색 상위 결과 다수가 "2026년부터 **상시 신청**으로 전환"이라고 서술했으나, tier 1 원문은 한시 접수(3.30~5.29)다. #33의 자산 기준 3.37억 오류와 같은 경로다. **tier 3은 감사에 사용하지 않는다**는 §1 원칙이 재확인됐다.

## 5. 파급 — FP baseline 무효

Sprint 3에서 확정한 **FP 0/22(0.0%)** 는 위 요건들이 `rule`에 없는 상태에서 측정됐다. 요건이 없으면 골든셋 케이스도 없고, 없는 요건은 위반될 수 없으므로 0%는 필연이었다.

따라서:

- PRD 5장 "FP 상한선 = 절대건수 0건"의 **근거가 현재 성립하지 않는다**
- `GoldenSetBaselineTest`의 FP 0건 assert는 **회귀 가드로서 무력하다** — 지키고 있는 대상이 비어 있다
- 요건 해소 후 골든셋을 확충하고 baseline을 재측정해야 PRD 수치가 의미를 갖는다

이건 Sprint 3 작업(#17)의 결함이 아니라 **측정 대상 자체가 불완전했다**는 뜻이다. 같은 하네스로 다시 재면 된다.

## 6. 미커버 사유가 기록되지 않는 문제

위 🔴 항목들이 *누락*인지 *의도적 제외*인지 지금은 판별할 수 없다. 예를 들어 임차보증금 3억 한도는 "묻지 않는 값이라 뺀 것"일 수 있는데, 그렇다면 조용히 통과시킬 게 아니라 **판정 불가로 고지**해야 한다.

→ 정책 레코드에 **`covered_requirements`**(원문 요건 ↔ 원자 매핑 + 미커버 사유: 스코프 밖 / 자가판정 불가 / 입력 미수집)가 필요하다. ADR-0008에서 다룬다.

**신청 채널은 별도 설계 판단이 필요하다** — 핸드오프 대상이 URL이 아닐 수 있다. 청약통장은 취급 은행 창구·앱, 청년월세는 주민센터 방문 또는 복지로 온라인이다. #48(out_of_scope 핸드오프)이 이미 "링크 목적지를 정책 데이터로 주입, 특정 창구 하드코딩 금지"로 정해뒀으므로, 같은 필드가 비(非)URL 채널도 담도록 설계하면 함께 해소된다.

> 배포 전이라 실사용자 노출은 없다. 위 FP 항목들은 **잠재 오판**이며 현재 실피해는 발생하지 않았다.

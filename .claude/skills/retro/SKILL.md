# retro — 회고 → 루프 갱신 (loop.md §9)

작업 사이클을 회고하고, 반복되는 교훈을 운영문서 규칙으로 승격 제안한다. **관찰·제안만 하고 확정은 사람이 한다.**

## 언제
- 작업 사이클(loop.md 1~7) 종료 시, 또는 사용자가 "회고"·"/retro" 호출 시.

## 절차
1. **수집** — 이번 사이클(들)에서:
   - 부족했던 정보/지식 (무엇을 몰라 헤맸나)
   - 반복된 판단 (매번 같은 결정을 되풀이했나)
   - 자동화·위임 가능 지점 (hook·에이전트·스킬로 뺄 수 있나)
   - 반복 차단된 게이트 (loop.md §8.5 카운트 — 같은 게이트가 자주 막혔나)
2. **분류·승격 판단**
   - 같은 교정 **3회 누적** → CLAUDE.md 규칙 승격 제안.
   - 같은 게이트 **반복 차단** → 해당 hook·리뷰어 기준을 loop.md에서 갱신 제안.
   - 1~2회성 → 기록만(승격 안 함).
3. **제안 (사람 승인 필수)**
   - CLAUDE.md → **직접 수정 금지**, diff로 제안(사람이 반영).
   - loop.md·기타 운영문서 → diff 제안 → 승인 후 반영.
   - 제품문서(PRD/SPEC/DOMAIN/ADR) 관련이면 그 문서 규칙(diff 제안·ADR)으로.
4. **기록** — 승격 안 된 관찰도 프로젝트 메모리에 남겨 다음 회고 입력으로.

## 출력 형식
- **관찰**: 수집 목록(범주별)
- **승격 제안**: 대상 문서 · diff · 근거 · (3회/반복) 충족 여부
- **보류**: 기록만 하는 관찰

## 원칙
- 회고는 관찰·제안만. 규칙 확정은 사람 승인.
- CLAUDE.md DO NOT 준수: CLAUDE.md·제품문서 직접 수정 금지(diff 제안).
- 1회성 우연을 규칙화하지 않는다(3회 기준). 과승격 경계.

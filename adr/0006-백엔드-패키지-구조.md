# ADR-0006: 백엔드 패키지 구조 — 도메인 중심 배치

- 상태: accepted (2026-08-10)
- 날짜: 2026-08-10
- 관련: ADR-0004(기술 스택), ADR-0003(판정 도메인 모델), PRD 9장(무인증·미저장), ARCHITECTURE.md §2

## Context

ADR-0004는 백엔드를 Java 21 + Spring Boot로 "판정 엔진 직접 구현"으로 정했으나, 백엔드 **내부 패키지 구조**는 어떤 ADR에서도 명시적으로 결정한 적이 없다. 현재 구조는 ADR-0003(계산 중심의 두꺼운 판정 도메인)과 PRD 9장(무인증·미저장)에서 파생돼 자리 잡았다. 이 ADR은 그 암묵적 결정을 사후에 명문화하고, 앞으로의 경계를 못 박는다.

전제 (깨지면 재검토):

- **저장이 없다.** PRD 9장 = 무인증·미저장·처리 후 폐기. DB·영속 상태가 없다.
- **핵심이 CRUD가 아니라 계산이다.** 도메인은 rule DSL 파싱 → 원자 평가 → Kleene 3치 조합 → verdict 사상이라는 두꺼운 로직(ADR-0003)이다.
- 규모는 1인 개발 + 단일 배포다.

## Decision

### D6. 기술 계층이 아니라 도메인 개념으로 패키지를 나눈다 (도메인 중심 / 헥사고날 지향)

- `domain/`(atom·rule·evaluate·kleene·scope·verdict)와 `policy/`는 **순수 POJO**로 두고 **프레임워크(`org.springframework`) 의존을 금지**한다.
- Spring은 **엣지에만** 둔다: `api/`(inbound 어댑터 — Controller·ExceptionHandler·DTO·요청 매퍼)와 `config/`(부트스트랩).
- 의존 방향은 **`api` → `domain`/`policy` 단방향.** 도메인은 web·HTTP·프레임워크를 모른다.
- 전통적 계층형(Controller→Service→Repository)의 **기술 계층 패키지를 만들지 않는다.** 특히 저장이 없으므로 Repository 계층을 두지 않는다.
- `api/`는 얇게 유지한다: HTTP 관심사 + DTO↔도메인 매핑만. **판정 로직은 도메인에만** 존재한다(런타임 LLM 부재 불변식과 함께 consistency-reviewer 대상).

## 기각된 대안

- **전통적 계층형 (Controller→Service→Repository).** 저장이 없어 Repository가 빈 껍데기가 될 뿐 아니라, 계산 중심 도메인을 얇은 Service 하나에 뭉치면 원자·규칙·verdict의 개념 경계가 흐려진다. 도메인의 두께가 계층이 아니라 개념 분할을 요구한다.
- **정책별 수직 슬라이스 (vertical slice per policy).** 원자·규칙 엔진은 모든 정책이 공유하는 자산이라 정책별로 코드를 수직 분할하면 중복·경계 혼란이 생긴다. 정책은 코드 슬라이스가 아니라 **데이터(rule DSL)로 추가**되는 것이 원칙이다(PRD 8장①).
- **Gradle 멀티모듈로 domain 물리 분리.** 현 규모(1인·단일 배포)에서 과하다. 패키지 경계 + 리뷰어 강제로 충분하다. 규모가 커지면 재검토한다.

## Consequences

- 도메인이 순수 POJO라 **Spring 컨텍스트 없이 빠른 단위 테스트**가 된다(현행 관행 유지 — PolicyEvaluator POJO 테스트, GlobalExceptionHandler standalone MockMvc).
- 패키지 경계는 컴파일러가 강제하지 않는다. `domain/`의 프레임워크 무의존은 **consistency-reviewer(게이트 3)**가 지킨다. 자동 강제를 원하면 ArchUnit류 테스트 도입을 별도 제안한다(외부 라이브러리 추가 승인 대상).
- **저장·인증이 도입되면(무저장 전제가 깨지면)** 재검토한다. 그때도 도메인 중심은 유지하되 저장은 outbound 어댑터(repository)로 붙인다 — 도메인이 저장을 의존하지 않는 방향을 지킨다.
- 이 ADR accept의 결과로 **ARCHITECTURE.md에 "백엔드 내부 구조" 항목 추가**가 수반된다(ARCHITECTURE는 ADR 결과로만 갱신).

# ADR-0005: 런타임 범위 게이트 (out_of_scope_gate)

- 상태: accepted (Phase 7, 2026-08-03 — 청년월세 특별지원 면제군 인코딩으로 트리거)
- 날짜: 2026-08-03
- 관련: DOMAIN §3.4·§4.6·§5.3, ADR-0003 D3, 이슈 #10

## Context

ADR-0003 D3는 `out_of_scope`를 **규칙의 정적 속성**으로 정의했다. `OutOfScopeClassifier`는 룰 트리만 보고(사용자 답변을 보지 않고) `household_aggregate` 원자 참조 여부로 사전분류한다. DOMAIN §3.4는 "out_of_scope는 런타임 논리값이 아니라 규칙의 정적 속성이다"라고 못박았다.

청년월세 특별지원(DOMAIN §5.3)은 이 모델의 빈틈을 드러낸다:

- 원 정책은 **원가구(부모) 소득**(`income_original`, `household_aggregate`)을 본다 → D3대로면 정책 전체가 out_of_scope.
- 이를 피하려 **면제군**(원가구 소득 평가를 면제받는 사람)만 판정 대상으로 좁히고, `income_original`을 규칙에서 배제했다.
- 면제 경로는 셋: ① 만 30세 이상 ② 혼인 ③ 시군구청장의 별도거주 인정. ①②는 자가판정 가능(`self`), ③은 행정 재량(`admin_discretion`, 항상 unknown §3.4).
- **문제:** 자가 면제 경로(①②)가 모두 false인 사용자(30세 미만·미혼)를 '부적합(ineligible)'으로 처리하면 **FN(놓친 적격자)** 이 발생한다. 이들은 우리가 배제한 `income_original` 경로 또는 행정 재량으로 자격이 있을 수 있기 때문이다. "판정 못 함"을 "해당 안 됨"으로 잘못 말하는 셈이다.

이 판정은 **사용자 답변(나이·혼인)에 의존**하므로 D3의 정적 분류로는 잡을 수 없다.

전제(ADR-0003 승계): 무인증·미저장 → 가구/원가구 합산값은 자가입력 담보 불가. `income_original`은 여전히 자가판정 불가. 이 전제가 깨지면(인증 도입 등) 본 결정도 재검토 대상.

## Decision

### D5. 런타임 범위 게이트 (out_of_scope_gate)

정책 레코드에 선택적 `out_of_scope_gate` 필드(Rule DSL 노드)를 둔다. 자격 `rule`과 **형제**이며 DSL 트리 밖이다(DOMAIN §4.4: "DSL은 자격 논리만 담당한다"). 게이트에는 **자가판정 가능한 면제 경로만** 담는다.

판정 순서:

```
1. household_aggregate 정적 사전분류 (D3, 불변)         → out_of_scope
2. base rule 평가
     base == FALSE                                      → ineligible
     base ∈ {TRUE, UNKNOWN}:
        게이트 없음                                      → base verdict
        게이트 있음 → gate 평가:
           gate == TRUE   → base verdict (TRUE→eligible / UNKNOWN→needs_review)
           gate == UNKNOWN→ needs_review (면제 입력 확인)
           gate == FALSE  → out_of_scope
```

핵심 규약:

- **게이트는 자가판정 경로만.** 행정 재량(`separate_residence`, 항상 unknown)은 게이트 멤버가 아니다 — 넣으면 `any_of`가 UNKNOWN에 갇혀 FALSE에 도달할 수 없어(§3.4) FALSE→out_of_scope 규칙이 무력화된다. 행정 재량 면제 경로는 out_of_scope 의미 자체에 흡수된다("자가 면제 불가 → 행정청 별도거주 인정 또는 원가구 소득 확인 필요").
- **base-FALSE 우선.** 자가판정으로 이미 탈락한 사용자(나이 범위 밖·무주택 아님 등)는 진짜 부적합이므로 ineligible이 out_of_scope보다 우선한다.
- **게이트 내부는 기존 Kleene 평가 그대로.** 새로운 것은 게이트의 최종 trilean을 '자격'이 아니라 '범위'로 재해석하는 것뿐이다. `RuleEvaluator`/`Trilean` 로직은 불변.
- `out_of_scope`의 출처가 둘로 늘어난다: (a) 정적 — `household_aggregate` 참조(D3) (b) 런타임 — 범위 게이트 FALSE(D5). 소비측(web)이 보는 verdict enum은 여전히 단일 `out_of_scope`이므로 **verdict.schema.json 무변경**이다.

## 기각된 대안

- **게이트를 base `all_of` 안에 중첩 + 노드 식별로 런타임 재매핑** (DOMAIN §4.6 원안 구조): `all_of` 안에서 게이트 FALSE는 상위 FALSE로 흡수돼 일반 ineligible과 구별하려면 특정 노드의 정체성을 런타임에 추적해야 한다. DSL이 자격 외 의미(범위)를 품게 되고 `rule-dsl.schema.json`(frozen) 변경이 필요하다. 형제 필드는 §4.4 경계와 일치하고 스키마를 건드리지 않는다.
- **게이트에 `separate_residence`(admin_discretion)를 포함** (DOMAIN §4.6·§5.3 원안): admin_discretion은 항상 unknown이라 `any_of`가 절대 FALSE가 되지 않는다. 대상 인구가 UNKNOWN→needs_review("행정청 확인")로 떨어져 §5.3이 요구하는 out_of_scope에 도달하지 못한다. 게이트는 자가 경로만 담고 admin 경로는 out_of_scope에 흡수하는 편이 정확하다. (`separate_residence` 원자는 카탈로그에 append-only로 남되 MVP 정책에서 미사용.)
- **면제 게이트 FALSE를 그냥 ineligible로** (현행 무처리): §5.3이 지적한 FN 그 자체.
- **base-FALSE보다 게이트를 우선(게이트 FALSE면 항상 out_of_scope)**: 나이 40세(base FALSE)도 out_of_scope가 되어 진짜 부적합을 범위 밖으로 오분류한다. 자가판정으로 확정 탈락한 사용자는 ineligible이 정확하다.
- **D3의 정적 분류를 런타임으로 일반화**: `household_aggregate`를 실제로 평가 시도하게 되는 D3 기각 대안 그대로다. D5는 "게이트 FALSE면 판정을 포기(범위 밖)"이지 합산값 평가 시도가 아니므로 다르다.

## Consequences

- 판정 조립부에 base·gate 2단 평가 + 우선순위 매핑이 추가된다. 도메인 계층(예: `ScopeGateEvaluator`)에 두어 컨트롤러를 얇게 유지하고, 판정 경로에 런타임 LLM이 없다는 불변식은 유지된다(consistency-reviewer 대상).
- `needs_review`의 unknown_reasons는 base·gate 중 unknown에 기여한 원자에서 모은다 — ADR-0003 후속과제 1(이슈 #8, 완료)의 흡수구조(contributingEvaluations)를 base·gate 각각에 적용해 조립한다.
- DOMAIN §3.4·§4.6·§5.3 갱신이 수반된다. ADR-0003 D3의 "정적 속성" 서술은 정적 경로에 한정되며, 런타임 게이트는 본 ADR이 관할한다(D3 결정 변경이 아니라 범위 명확화이므로 supersede 아님).
- 새 원자 `household_composition{scope:self, married}` 평가기가 추가된다. `scope:aggregate` 분기는 이슈 #9 소관이며 그전까지 D4 fail-loud를 유지한다.
- 신규 입력 변수 `married`(bool)가 API answers에 추가된다(contracts/openapi.yaml).

# ADR-0003: 판정 도메인 모델

- 상태: accepted (Phase 7, 2026-07-27 — 청년 주택드림 청약통장 인코딩으로 트리거 조건 충족)
- 날짜: 2026-07-19

## Context

Phase 4에서 DOMAIN §1~4를 작성하며 판정 엔진의 구조를 정했다. 이 결정들은 DOMAIN 본문에 "무엇/어떻게"로 기록됐으나, "왜 이 구조인가"와 기각된 대안은 남지 않았다. 리셋되는 에이전트가 기각된 선택지를 반복 제안하는 것을 막기 위해(ADR-0001), 구조적 결정의 근거를 여기 박는다.

전제:
- 무인증·미저장 → 사용자가 '모름'으로 답할 수 있고, 가구 합산 값은 자가입력으로 담보 불가.
- 정책은 비정형·다수·고갱신 → 정책 추가 비용을 낮게 유지해야 한다(PRD 6장 설계 원칙, 8장①).
- 이 전제가 깨지면(예: 인증 도입으로 행정 데이터 조회 가능) 본 결정은 재검토 대상.

Phase 7에서 청년 주택드림 청약통장(DOMAIN §5.1)을 실제로 인코딩해 D1~D3를 코드로 검증했다(backend `domain/` 패키지, 76개 테스트 — Trilean 진리표, RuleDslParser, OutOfScopeClassifier, RuleEvaluator). 그 과정에서 드러난 보강 사항을 D4로 추가하고 accept로 전환한다.

## Decision

### D1. 요건 원자 + 선언적 Rule DSL

정책 로직을 정책마다 코드로 짜지 않고, 재사용 가능한 요건 원자(DOMAIN §2) 위에 정책별 선언적 규칙 트리(Rule DSL, §4)를 얹는다. 정책 추가 = 규칙 데이터 한 건.

### D2. Kleene 강 3치 논리

원자 평가값을 {true, false, unknown} 3치로 두고 all_of/any_of/not을 Kleene 강 논리로 조합한다(§3). unknown을 일급(first-class) 값으로 다룬다.

### D3. 값 유형 기반 out_of_scope 사전분류

원자에 값 유형(self / household_aggregate / admin_discretion, §2.2)을 부여하고, `household_aggregate` 원자를 참조하는 정책은 런타임 평가 이전에 `out_of_scope`로 사전분류한다(§3.4). out_of_scope는 계산 결과가 아니라 규칙의 정적 속성이다.

### D4. 원자 카탈로그는 미구현 원자도 값 유형을 전원 등록, 평가기 부재는 fail-loud

D3의 out_of_scope 정적분류는 원자 카탈로그 전체(12개)의 값 유형 매핑에 의존한다 — 특정 정책이 어떤 원자를 참조하는지와 무관하게, 분류기가 그 원자의 값 유형을 항상 조회할 수 있어야 하기 때문이다. 따라서 평가기(evaluator)가 아직 없는 원자도 값 유형만은 카탈로그에 전원 등록한다. 단, 값 유형이 확정되지 않은 원자(예: `household_composition` — §2.3 각주에 self/household_aggregate 중 파라미터에 따라 갈린다고 열려 있음)를 실제로 평가하려는 시도는 조용히 넘어가지 않고 예외로 fail-loud 처리해, 미확정 상태에서 오분류(특히 out_of_scope 누락)가 조용히 발생하는 것을 막는다.

## 기각된 대안

### D1
- **정책별 로직 하드코딩** — 정책이 늘 때마다 코드·테스트가 선형 이상으로 증가. 고갱신성(매년 기준 변경)에 코드 수정이 따라붙어 회귀 위험. PRD 6장이 "규칙 데이터 한 건" 원칙을 이미 앵커.

### D2
- **2치 논리 + unknown을 부적합으로 흡수** — 경계 사용자에게 잘못된 '부적합' 확신을 준다(FN 증가, PRD 3장 문제정의와 충돌).
- **2치 + unknown을 항상 needs_review로 일괄** — `unknown OR true = true`의 대체 경로 해소가 불가능해져, 청년월세 면제군처럼 재량 경로가 있어도 무조건 '추가 확인 필요'로 떨어진다. 판정 깊이 손실.
- **unknown을 별도 사이드채널로 처리** — 조합 규칙이 원자마다 특수분기되어 DSL 선언성이 깨진다.

### D3
- **out_of_scope를 런타임 계산값으로** — 가구합산 원자를 실제로 '평가'하려 시도하게 되어, 자가입력 불가 값에 무리한 판정을 유발(오판율↑). 사전분류가 "아예 시도하지 않음"을 강제한다.
- **household_aggregate와 admin_discretion을 한 값 유형으로 통합** — 전자는 정책 전체 배제, 후자는 대체 경로 해소 가능이라 처리가 달라 분리가 필요(§2.2).

### D4
- **미구현 원자는 카탈로그에서 아예 생략** — OutOfScopeClassifier가 카탈로그에 없는 원자를 만나면 판정 자체를 할 수 없어, D3의 "정적 분류는 항상 성립해야 한다"는 전제가 깨진다.
- **값 유형 미확정 원자에 임의 기본값을 주고 조용히 진행** — `household_composition`을 그냥 `self`로 확정해버리면, 실제로는 household_aggregate scope가 필요한 정책이 들어왔을 때 out_of_scope 판정을 누락(오탐 아닌 미탐 — 자가판정 불가를 가능으로 잘못 흘려보낼 위험)한다. fail-loud가 이 실패 모드를 막는다.

## Consequences

- 판정 엔진은 원자 평가기 + Kleene 조합기 + 사전분류기 세 부분으로 구현된다.
- 새 정책이 새 원자를 요구할 때만 비용 발생(카탈로그·스키마·평가기 추가). `rule-dsl.schema.json`의 atom enum이 그 지점을 사람 승인 게이트로 만든다.
- unknown 일급화로 verdict에 출처 태그(§3.1)가 실린다 — `verdict.schema.json`에 반영됨.
- **후속 과제 (다음 정책 인코딩 전 필수 선행작업, DOMAIN §5.2·§5.3):**
  1. `unknown_reasons` 수집이 아직 트리의 흡수 구조를 반영하지 않는다 — 현재는 UNKNOWN으로 평가된 원자를 트리 위치와 무관하게 전부 모으는 방식이라, 이번 청년 주택드림처럼 단일 `all_of` 트리에서는 정확하지만(AND의 흡수 성질상 우연히 일치), `any_of`가 중첩되는 정책(§4.6·§5.3 청년월세 면제군 구조)에서는 이미 다른 형제가 TRUE로 흡수시켜 결과에 기여하지 않은 UNKNOWN 원자의 사유까지 새어나올 수 있다. `any_of` 중첩 정책 인코딩 전에 흡수원소를 반영한 재설계가 필요하다.
  2. `household_composition`의 값 유형(self/household_aggregate, §2.3 각주)이 여전히 미확정이다 — D4의 fail-loud가 조용한 오분류는 막지만, 이 원자를 실제로 쓰는 정책(버팀목 기혼자 케이스 등, DOMAIN §5.2 열린 문제)을 인코딩하기 전에는 반드시 확정해야 한다.
- accepted (Phase 7): 위 후속 과제는 accept를 막지 않되, 다음 정책 인코딩 착수 조건으로 남긴다.
